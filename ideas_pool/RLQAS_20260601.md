## 3. 跨分子与跨键长泛用性分析

### 3.1 跨键长迁移（同一分子）：在理论上可行

**为什么可行**：
- 算符池由 `(n_electrons, n_orbitals)` 决定，与键长无关。LiH (2,6) 在任意键长的 FOP 算符池完全相同，policy 网络权重可直接迁移。
- 奖励信号结构一致：`reward = -(E_VQE - E_FCI)`，每个键长均归一化到化学精度 1.6 mHa。
- 势能面连续，相邻键长最优算符序列高度重叠。

**潜在挑战**：
- 键长远端（R > 3Å 解离极限）：静态关联增强，不同算符集变重要，泛化可能失效。
- 稀疏奖励 + 短 episode：单个键长训练量不足可能导致欠学习。

**当前代码状态**：  
`experiment/transfer.py` 已有骨架实现（`train_multi_geometry`, `evaluate_transfer`），但**从未运行过**，`results/` 目录中无任何迁移实验数据。仅支持 PPO，不支持 GRPO/GiGPO。

### 3.2 跨分子迁移：当前架构不支持

不同分子的算符池大小不同（action space 维度不同），无法直接迁移 policy 权重。需要 universal embedding 或 meta-learning，属于未来工作。

### 3.3 推荐的 E4 实验设计

```
训练集：LiH 12q，R ∈ {0.9, 1.4, 2.0, 2.8} Å（稀疏，4 个点）
测试集：LiH 12q，R ∈ {1.0, 1.1, 1.2, 1.3, 1.5, 1.6, 1.7, 1.8, 2.2, 2.5} Å（稠密，10 个点）

对比三种模式：
  A. Zero-shot：直接用训练好的 agent，不做任何梯度更新
  B. Fine-tune：从训练权重出发，用 50 episode 微调
  C. From-scratch：在每个测试键长从头训练 50 episode

核心问题：
  1. Zero-shot 是否在平衡键长附近（R=1.0~1.8 Å）达到化学精度？
  2. Fine-tune 比 from-scratch 快几倍？
  3. 解离极限（R>2.5 Å）下是否失效？
```

正负结果都有科学价值（正：策略可迁移；负：解离极限需特殊处理）。

## 6. QOP 的正确实现方式

### 6.1 关键发现

TenCirChem 原生支持 QOP，接口为：

```python
# FOP（默认）
u_fop = UCCSD(mol, mode="fermion", active_space=(2,5))

# QOP（去掉 JW 变换后的 Z 串）
u_qop = UCCSD(mol, mode="qubit", active_space=(2,5))
```

**物理含义**：`mode="qubit"` 在 Jordan-Wigner 变换后去掉 Pauli 串中的 Z 算符，产生更短的量子电路（Qubit-ADAPT-VQE 方法），以轻微的对称性损失换取 CNOT 数的显著减少。

**实测数据（LiH，active_space=(2,5), 10q）**：
- FOP (mode=fermion)：318 CNOTs，误差 0.0000 mHa
- QOP (mode=qubit)：240 CNOTs，误差 0.0000 mHa
- **CNOT 减少 24.5%，精度不变**

### 6.2 当前 rlqas-chem QOP 实现的根本性错误

现有 `QubitUCCSearchController` 的问题：
1. 自己从哈密顿量 off-diagonal 项提取 Pauli 串构建算符池（完全绕过 TenCirChem）
2. 实际训练环境仍是费米子 `UCCSearchEnv`（`mode="fermion"`）
3. `qubit_pool` 只用于报告 `performance_metrics["qubit_pool_size"]` 这一个数字
4. **结论：当前 QOP 搜索 = FOP 搜索 + 一个假统计数字**

### 6.3 正确的修复方案（给 Ralph 的 PRD）

修复核心：在 `UCCCircuitBuilder` / `UCCSearchEnv` 初始化时，当 `operator_pool="qop"` 时，向 TenCirChem UCCSD 传入 `mode="qubit"`。算符池大小、动作空间维度不变，仅线路实现不同。同时需要：
1. `UCCCircuitBuilder`：新增 `mode` 参数，传递给 TenCirChem UCCSD
2. `api.py`：search() 结果中新增 `cnot_count` 字段
3. `QubitUCCSearchController`：废弃或重写为正确实现
4. 通过所有新增的 QOP 验收测试
